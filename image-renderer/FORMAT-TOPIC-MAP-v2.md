# SOAR: choosing the best image for a topic (v2, 18 Oct 2026)

Replaces FORMAT-TOPIC-MAP.md (v1). Draft for James to review.

**Built from four independent inputs:**
1. James's Drive: DESIGN-CATALOGUE, STYLE-GUIDE, content strategy, image briefs, revision log, Master Posts (real topics and real format use).
2. A web research pass: Abela, Zelazny, Roam, Duarte, Lengler and Eppler, NN/g, FT Visual Vocabulary, Mayer, Larkin and Simon, Peltier Tech, Socialinsider.
3. An independent Codex derivation: it picked the best representation for 40 topics blind, then audited this map and all 32 formats against their guardrails. Its files: `out/mapping-review/blind-mapping.md` and `review.md`.
4. Claude's own judgement. Where a pick rests only on this, it is marked "judgement".

**What is not evidenced:** no sourced data exists on how any diagram type performs for career content. The only measured data is Socialinsider's company-page benchmark (multi-image 6.60%, documents about 6.1-7.0%, single image 4.85%, text 4.00%). It does not transfer cleanly to a personal profile and says nothing about diagram type. These picks are editorial judgement, not performance claims.

James's rule on timing: posting dates are not known in advance, so no 72-hour or three-post spacing rule is applied here.

## 1. Routing gate (use before any table)

1. Write the single thing the reader should understand, the evidence available, and what they should do next. For a broad topic, pick the specific lesson first.
2. If exact wording, a document's layout, or an interface location is the lesson, use a text example, a reconstructed document, or a real screenshot. Label reconstructions and invented examples.
3. If the claim is about measured numbers, look at the actual data before choosing a chart. If a chart adds nothing, use sourced text. Always show the cohort, date and denominator.
4. Otherwise name the relationship: comparison, revision, correspondence, order, time, prerequisites, conditional action, roles and authority, feedback, possible causes, scope, overlap, evidence support.
5. Pick the format that truthfully encodes that relationship. If none does, use a new layout or text. Never imply order, cause or quantity through connectors, area or width that the facts do not support.
6. Check one lesson at phone width. If it does not fit, split the post or change treatment. Variety never overrides the relationship.

## 3. Types the 32 formats do not cover (suggest adding)

These are proposed, not catalogue IDs. All would be built in the same clean editorial style.

| Proposed type | What it shows | Topics that need it | Why the 32 do not cover it |
|---|---|---|---|
| Decision swimlane | Roles in lanes with staged hand-offs and recommend/approve labels | 30 | E06 merges inputs; X11 has no authority |
| Human-AI verification swimlane | Facts, draft, human check, approval | 35 | E03 has no owners or revision loop |
| Wait/work strip | Active steps vs queues and hand-offs, unscaled unless real timings | 36 | N05 shows milestones, not waiting |
| Contextual data chart | A sourced number against an honest base on a common scale | 38 | No numeric chart in the 32. Exact type needs the data |
| Stage-conversion bars | Counts or rates at ordered events for a defined cohort and window | 39 | N03 is qualitative; X15 is investigation |
| Plain ranked bar (W) | Ranking by one measure | Rankings with real data | Zelazny and FT Visual Vocabulary; none in the 32 |
| Wireflow (W) | Real screens linked by arrows | Multi-screen how-tos | NN/g prefers it to abstract flowcharts; E08 shows one screen |
| Journey map, waterfall, Sankey (W) | Candidate experience; how an offer is built up; losses through a process | Narrow cases | Sources suggest them; lower priority, unverified for this audience |

## 4. The 32 formats

"Silhouette" is the visual shape. Several are single-member, so do not assume a same-shape swap is always available. Pillars are soft: every format works for any topic with its lesson shape.

| ID | Format | Use it when | Guardrail to respect | Silhouette |
|---|---|---|---|---|
| E01 | Side-by-side | Two options, same dimensions | No universal winner. More than two options needs a table | Two columns |
| E02 | Before/after | One real revision | Label invented examples | Stacked pair |
| E03 | Short sequence | 2-4 ordered steps | Arrows mean real order. Undated steps are E03, dated are N05 | Vertical list |
| E04 | Branching decision | A question changes the action | Branches must lead to different actions | Branch |
| E05 | Annotated anatomy | Why one object works | 2-3 callouts. Annotating one object is not before/after | One object plus callouts |
| E06 | Converging inputs | Several sources inform one view | Means "helps define", never "decides" | Inputs to one box |
| E07 | Fill-in worksheet | A structure to complete | Only useful fields | Form |
| E08 | Screenshot annotation (schematic) | One UI action | A labelled schematic, not a real screenshot. For a real one, use a real screenshot instead | Interface frame |
| E09 | Requirement-to-proof pairs | One need, one proof | Aligned rows, no crossing. Many proofs per need needs X02 | Two columns joined |
| E10 | Example dialogue | A concrete reply | Mark as example. Teaches wording, not why it works | Speech blocks |
| N01 | Two-axis matrix | Two named criteria | Label axes. Placement is judgement, not data | Quadrants |
| N02 | Spectrum | Many positions on a real range | No fake numbers. Two answers is E02 | Line with points |
| N03 | Filter stages | Qualitative narrowing | Widths and shape must not imply quantity | Narrowing stack |
| N04 | Feedback loop | A repeat that changes | Must truly repeat and change the next cycle | Loop |
| N05 | Timeline | Real days or milestones | Real day labels. No equal-time implication | Vertical timeline |
| N06 | Ownership ladder | Ordered scope | No promise of promotion. Levels vary by company | Steps |
| N07 | Visible and hidden | Stated vs to ask | Say "not stated". Never imply a percentage | Two-part layers |
| N08 | Overlap | A meaningful intersection | Only sets whose overlap has meaning. It cannot rank | Venn |
| N09 | Evidence layers | Claim, example, result | Few layers. Not the same as STAR | Stack |
| N10 | Evidence tree | One claim, several proofs | Distinct proofs | Tree |
| X02 | Coverage grid | Needs against proof | Define partial, full, missing. Coverage is not effectiveness | Grid |
| X03 | Bottleneck and repair | A weak link already established | Diagnose first | Flow with a break |
| X04 | Dependency map | Prerequisites | Show direction. Do not claim an outcome | Inputs to one |
| X05 | Alternative routes | Several valid paths | Not all routes equally open. Conditions need E04 | Branching map |
| X06 | Backcasting | Work back from a goal | Needs derivable requirements | Stepped list |
| X08 | Zoom-in | Broad to specific | Specific is not the same as true | Nested boxes |
| X10 | Fishbone | Possible causes to check | Causes are hypotheses, not proof | Fishbone |
| X11 | Stakeholder network | People with different roles | Needs meaningful links, else use pairs | Hub and spokes |
| X12 | Experiment board | A small test and a decision | Show why this test | Four cells |
| X14 | Remove / keep / add | An edit plan | Distinct actions | Three rows |
| X15 | Hypothesis, evidence, test | Reasoning without proof | Hypothesis arrows are not causes | Chain |

- STAR now uses E05/E07, not N09. Vague vs strong answers use E02, not N02. Question intent uses an adapted E09, not N07. The resume scan uses a reconstructed document, not N07.
- Hiring decisions get a swimlane. E06 only means "helps define".
- "First 6 seconds" is removed: no source for the number.
- The claim that "every family has at least two formats" was false and is removed. Several silhouettes have one member.
- Removed v1 references to M01, M07, M12, M22, M26, M29 as if they were among the 32. They are catalogue metaphors, not formats. Use metaphors only when the exact object-to-meaning mapping fits and has not been retired.
- Retired and excluded: B01 funnel, B05 magnifier, B09 compass objects. M07 compass is also treated as retired (decided 18 Oct 2026: the style guide says to retire a concept when James rejects it, so a rejected compass is not reintroduced under another ID).
